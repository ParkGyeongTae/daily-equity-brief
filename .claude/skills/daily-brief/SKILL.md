# 브리프 작성 절차

이 문서는 **브리프를 쓸 때만** 읽는다. 상시 규칙(역할, 하지 않는 것, 산출물 경로, 커밋)은 `AGENTS.md`에 있고
매 세션 로드된다. 둘이 어긋나면 `AGENTS.md`가 우선한다.

## 1단계 — 오늘 파일 확인과 제외 목록

이 절차는 **사람 없이 매일 07:00에 실행된다.** 그러므로 먼저 확인할 것은 "오늘 이미 썼는가"다.
재시도·수동 요청이 겹치면 같은 날 두 번째 브리프를 쓰게 되고, 그건 아무도 요청하지 않은 결과다.

```bash
# 오늘 파일이 이미 있으면 새로 쓰지 않는다.
TODAY=$(TZ=Asia/Seoul date +%F)
ls briefs/$TODAY-*.md 2>/dev/null
```

- **파일이 이미 있으면 여기서 끝낸다.** 그 경로와 종목을 보고하고, 새 브리프를 쓰지 않는다.
  하루 두 건은 **사람이 명시적으로 두 번째를 요청했을 때만** 쓴다.
- 파일이 없으면 아래로 간다.

그다음 제외 목록이다. 후보를 찾기 **전에** 만든다. 나중에 하면 이미 쓴 종목에 시간을 버린다.

```bash
# 최근 7일 내 작성한 브리프의 종목 코드
# date 는 BSD(macOS)와 GNU(Linux)의 상대날짜 문법이 다르다 — 둘 다 시도한다.
CUTOFF=$(TZ=Asia/Seoul date -v-7d +%F 2>/dev/null || TZ=Asia/Seoul date -d '7 days ago' +%F)
ls briefs/*.md 2>/dev/null \
  | sed -n 's#briefs/\([0-9-]\{10\}\)-\(.*\)\.md#\1 \2#p' \
  | awk -v cutoff="$CUTOFF" '$1 >= cutoff'
```

- 이 목록이 **오늘 쓸 수 없는 종목**이다.
- 제외 목록의 근거는 **이 저장소의 `briefs/`뿐이다.** 다른 저장소나 외부 아카이브를 뒤지지 않고,
  보고서에도 그런 것을 확인했다고 쓰지 않는다.
- 7일은 **작성일 기준**이다. 같은 회사를 8일 만에 다시 쓰는 것은 허용되지만, 그때는 직전 브리프 이후
  **무엇이 달라졌는지**를 `## 1. 왜 지금 이 종목인가`에 명시한다.

## 2단계 — 시장 판정과 후보 발굴

**시장은 날짜로 정한다 — 짝수일은 미국, 홀수일은 한국.** 그날의 검색 결과에 따라 시장이 갈리면
재현되지 않으므로, 뉴스를 찾기 **전에** 먼저 판정한다.

```bash
# KST 고정. TZ를 빼면 로컬 타임존 날짜로 판정돼 시장이 뒤집힌다.
# 10#을 빼면 08·09일에 8진수로 해석돼 죽는다.
[ $(( 10#$(TZ=Asia/Seoul date +%d) % 2 )) -eq 0 ] && echo "미국 (SEC EDGAR)" || echo "한국 (DART/KIND)"
```

- 판정 기준은 **KST 날짜**다. 미국 종목을 쓰는 날에도 기준 종가는 직전 **확정** 거래일이므로,
  한국 날짜보다 하루 밀리는 것이 정상이다.
- **휴장은 시장을 바꾸는 사유가 아니다.** 연휴·주말이라 그 시장이 쉬어도 날짜 규칙을 그대로 지킨다.
  **뉴스와 가격을 분리한다** — 뉴스는 휴장과 무관하게 **캘린더 날짜 최근 3일**에서 찾고,
  가격만 **직전 확정 거래일 종가**를 쓴다. 휴장일에도 기업 뉴스는 나오므로 뉴스 창을 뒤로
  밀지 않는다(9/25 실행이면 뉴스는 9/23~9/25, 기준 종가일은 9/23).
  대신 **휴장 사실과 기준 종가일을 0절 스냅샷과 7절에 적는다.** 날짜 규칙이 흔들리지 않는 것이
  이 편성의 목적이다.
- **시장을 바꾸는 예외는 하나뿐이고, 기록하고 쓴다.** 점수표 ②검증 가능성을 통과하는 후보가
  하나도 없으면 다른 시장으로 넘어간다. 멈춰서 묻지는 않되, **왜 넘어갔는지를 보고서 1절과
  최종 보고에 남긴다. 조용히 바꾸지 않는다.**
- 31일 다음은 1일이라 홀수가 연달아 오고, 그만큼 한국이 연 7회가량 많아진다. 알면서 두는 편차이니 보정하지 않는다.

정해진 시장에서, **최근 3일**(오늘 포함, KST 캘린더 기준) 이내 뉴스로 후보 **3~5개**를 뽑는다.
**거래일이 아니라 캘린더 날짜다** — 연휴·주말에 터진 뉴스를 놓치지 않기 위해서다. 휴장 중에 나온
뉴스는 확인할 공시가 아직 접수되지 않았을 수 있지만, 그건 점수표 **②검증 가능성이 걸러낼 몫**이지
뉴스 창을 좁힐 이유가 아니다.
뉴스는 후보를 만드는 데만 쓰고, 그 숫자는 쓰지 않는다.

### 발굴 경로 — 1차는 공시 접수 목록, 2차가 뉴스

시장을 날짜로 고정한 이유는 재현성이다. 발굴 경로를 매일 새로 정하면 그 재현성이 반쯤 무의미해진다.
그래서 **먼저 공시 접수 목록에서 사건을 찾고, 그것으로 3~5개가 안 차면 뉴스 검색으로 보강한다.**
공시 접수 목록에서 출발하면 점수표 ②검증 가능성이 이미 확보된 상태로 후보가 만들어진다.

`.env`는 **셸로 `source` 할 수 없다** — `SEC_USER_AGENT` 값에 공백이 있어 `set -a; . ./.env`는
"command not found"로 죽는다. 아래처럼 필요한 값만 꺼낸다.

```bash
# 미국 — EDGAR 전문검색. 실적 발표(8-K Item 2.02) 최근 3일. UA 없으면 403이다.
UA=$(grep -E '^SEC_USER_AGENT=' .env | cut -d= -f2-)
FROM=$(TZ=Asia/Seoul date -v-2d +%F 2>/dev/null || TZ=Asia/Seoul date -d '2 days ago' +%F)
curl -s -H "User-Agent: $UA" \
  "https://efts.sec.gov/LATEST/search-index?q=%22Item%202.02%22&forms=8-K&startdt=$FROM&enddt=$(TZ=Asia/Seoul date +%F)" \
  | python3 -c 'import json,sys
d=json.load(sys.stdin)
print("총", d["hits"]["total"]["value"], "건")
for h in d["hits"]["hits"]:
    s=h["_source"]; print(s.get("file_date"), "|", (s.get("display_names") or ["?"])[0])'
```

```bash
# 한국 — DART 접수 목록. pblntf_ty=B 주요사항보고, I 거래소 수시공시. corp_cls Y=유가증권 K=코스닥.
K=$(grep -E '^DART_API_KEY=' .env | cut -d= -f2-)
BGN=$(TZ=Asia/Seoul date -v-2d +%Y%m%d 2>/dev/null || TZ=Asia/Seoul date -d '2 days ago' +%Y%m%d)
curl -s "https://opendart.fss.or.kr/api/list.json?crtfc_key=$K&bgn_de=$BGN&end_de=$(TZ=Asia/Seoul date +%Y%m%d)&pblntf_ty=B&corp_cls=Y&page_count=30" \
  | python3 -c 'import json,sys
d=json.load(sys.stdin)
print("status:", d.get("status"), d.get("message"))
for it in (d.get("list") or []): print(it["rcept_dt"], "|", it["corp_name"], "|", it["report_nm"])'
```

- 검색어·공시유형을 바꿨으면 **무엇으로 바꿨는지 `## 방법론 · 재현`에 적는다.** 경로를 바꾸는 것은
  허용되지만 조용히 바꾸는 것은 허용되지 않는다.
- EDGAR 전문검색은 색인이 하루가량 늦을 수 있다. 접수 목록이 비면 뉴스 검색으로 넘어가고,
  그 사실을 기록한다.
- **키가 없으면 그 경로를 포기하고 뉴스로 간다.** `DART_API_KEY`나 `SEC_USER_AGENT`가 환경에 없는
  실행 환경이 있다(무인 실행은 저장소의 `.env`를 갖고 있지 않다). 그때는 **시장을 바꾸지 않고**
  뉴스 검색으로 후보를 만들고, **키가 없어 접수 목록을 못 봤다는 사실을 `## 방법론 · 재현`에 적는다.**
  다만 ②검증 가능성은 여전히 공시 원문으로 확인해야 한다 — EDGAR 문서 본문은 UA 없이도
  받아지는 경우가 있으니 거기서 막히면 그 사실도 함께 적는다.
- **미국 실적 발표는 KST 새벽(장 마감 직후)이나 밤(장 개장 전)에 나온다.** 07:00 실행은 전날 마감 후
  접수분까지 보이지만 **당일 아침 접수분은 아직 없다.** 한국도 같다 — 07:00은 DART 접수 개시 전이라
  당일 접수분이 없다. 뉴스 창을 캘린더 3일로 두는 이유가 이것이다.

우선순위가 높은 뉴스 유형 — **공시로 확인 가능한 사건**:

- 실적 발표, 가이던스 변경
- 계약·수주·인수합병·설비투자 발표
- 규제 승인·제재, 소송 결과
- 자본 이벤트(증자, 자사주, 배당 정책 변경, 지분 변동)

후보에서 **빼는** 뉴스 유형 — 확인할 원문이 없는 것:

- "~할 전망", "~로 알려졌다" 수준의 관측·루머
- 목표주가 상향/하향 같은 증권사 코멘트 자체
- 테마·섹터 기사에 이름만 묶여 나온 경우

## 3단계 — 선별: "매매하기 매력적인"의 정의

**오를 것 같은 종목이 아니라, 조건을 명확하게 쓸 수 있는 종목을 고른다.**
진입·무효화 조건을 가격으로 적을 수 없는 종목은 아무리 이야기가 좋아도 이 저장소에서는 매력적이지 않다.

후보마다 아래 5개를 상(2)/중(1)/하(0)로 채워 표로 만들고, 합계로 스스로 하나를 고른다.

| 기준 | 무엇을 보는가 | 하(0)의 예 |
|---|---|---|
| ① 촉매의 구체성 | 뉴스가 가리키는 사건이 **날짜와 숫자를 가진 사건**인가 | "AI 수혜 기대" |
| ② 검증 가능성 | 그 사건을 확인할 **1차 공시가 실제로 존재**하는가(제출일까지 확인) | 공시 없음, IR 구두 언급뿐 |
| ③ 유동성 | 20일 평균 거래대금이 충분한가(얇으면 조건이 체결되지 않는다) | 호가가 비어 있는 종목 |
| ④ 일정 근접성 | 다음 확인 이벤트(실적 발표 등)가 **가까운가** | 다음 공시까지 3개월 이상 |
| ⑤ 가격 위치의 명확성 | 지지/저항이 뚜렷해 **무효화 조건을 가격으로 쓸 수 있는가** | 신고가 공백 구간, 근거 레벨 없음 |

- ②가 0이면 **합계와 무관하게 탈락**한다. 확인할 원문이 없으면 이 저장소는 쓸 게 없다.
- 동점이면 ⑤가 높은 쪽을 고른다. 그래도 같으면 ①이 높은 쪽. 그래도 같으면 **원자료가 온전한 쪽**이다 —
  최근 20봉에 결측이 있으면 발표 당일 반응을 원자료로 잴 수 없다. 여기까지도 같으면 티커 알파벳 순으로
  고르고 **그 사실을 점수표 아래에 적는다.** 순서가 끝까지 정해져 있어야 즉석에서 기준을 만들지 않는다.
- **선정은 스스로 한다 — 사용자에게 묻지 않는다.** 대신 **점수표를 보고서 `## 1. 왜 지금 이 종목인가`에
  그대로 싣는다.** 탈락한 후보와 그 점수가 함께 남아야, 나중에 "왜 하필 이 종목이었나"를 되짚을 수 있다.
  묻지 않는 대신 기록으로 감사 가능하게 만드는 것이 이 저장소의 방식이다.
- 점수는 근거와 함께 매긴다. ②는 **실제로 공시를 찾아 제출일을 확인한 뒤**에만 1 이상을 준다 —
  "있을 것 같다"는 0이다. 여기서 점수를 후하게 주면 4단계에서 수집할 원문이 없어 되돌아와야 한다.
- **③유동성과 ⑤가격 위치는 가격 데이터 없이 매길 수 없다.** 그러므로 후보 전부의 일봉을 이 단계에서
  받는다(4단계의 `$SCRATCH` 정의를 먼저 읽는다). 선정된 종목만 2y·5y로 다시 받으면 된다.
- 후보 일봉 수집에서 **결측·실패가 난 후보는 그 사실을 점수표 비고에 적는다.** 조용히 후보에서 빼지 않는다.

```bash
# 후보 채점용 — 1년 일봉이면 ③⑤에 충분하다.
python3 scripts/fetch_ohlcv.py <후보티커> --range 1y --interval 1d -o "$SCRATCH/<후보티커>-1d.json"
python3 scripts/technicals.py "$SCRATCH/<후보티커>-1d.json" --drop-unconfirmed --emit table
```

③은 표의 **20봉 평균 거래대금** 행으로, ⑤는 `--emit levels`의 클러스터 유무와 "공백 구간" 경고로 매긴다.
손으로 계산하지 않는다.

## 4단계 — 수집

공시 읽기는 분량이 크다. **`filings-researcher` 서브에이전트에 위임하고 메인 컨텍스트는 비워둔다.**
위임할 때 넘기는 것은 네 가지다 — 종목/티커, 3단계에서 정한 **확인할 질문**, 회계연도 기준,
그리고 **2절 산업 소절에 쓸 항목**(한국: 사업보고서 II장의 산업의 특성·성장성·경기변동·시장점유율 /
미국: 10-K Item 1의 Competition·Customers·Raw Materials·Seasonality). 산업 배경도 공시에서 온다.
받는 것은 그 에이전트가 정의한 다섯 덩어리(열어본 문서 / 수치 / 사업 구조 / 산업 배경 /
질문별 확인·반박)다.
범위를 주지 않고 "조사해줘"라고 던지면 수백 페이지를 읽고 돌아오므로 **질문을 반드시 함께 넘긴다.**

시장 데이터는 위임하지 않는다. 아래 스크립트로 메인 세션이 직접 받는다.

### 1차 출처 (분석 근거)

| 시장 | 출처 | 주로 보는 문서 |
|---|---|---|
| 한국 | DART (dart.fss.or.kr), KIND (kind.krx.co.kr) | 사업보고서, 분기·반기보고서, 주요사항보고서, 수시공시 |
| 미국 | SEC EDGAR (sec.gov/edgar) | 10-K, 10-Q, 8-K, DEF 14A, 실적 발표 보도자료(EX-99) |

- 공시 원문 URL을 `## 출처`에 전부 남긴다. 링크 없는 주장은 쓰지 않는다.
- IR 페이지의 실적 발표 자료는 보조 자료다. 공시본이 있으면 공시본을 우선한다.
- 종목 선정용 뉴스는 출처에 포함하되 "선정 계기"로 명확히 구분한다.
- API 키는 `.env`에 있다(`.env.template` 참고). EDGAR는 `SEC_USER_AGENT` 헤더가 없으면 403이다.
  `.env`를 `source`하지 말고 2단계처럼 `grep … | cut -d= -f2-`로 필요한 값만 꺼낸다(값에 공백이 있다).

### 시장 데이터 (타이밍 근거)

주가·거래량·시가총액은 공시에 없다. **이 항목만 2차 출처를 허용한다.**

원자료는 **저장소 밖 스크래치패드**에 둔다. 아래 명령들이 쓰는 `$SCRATCH`를 먼저 정의한다.

```bash
# 날짜로 고정한다. 셸 상태는 명령 사이에 유지되지 않으므로, 4·5단계에서 명령을 부를 때마다
# 이 줄을 앞에 붙인다. mktemp 로 잡으면 호출마다 새 폴더가 생겨 원자료와 지표가 갈라진다.
SCRATCH="${TMPDIR:-/tmp}/equity-brief/$(TZ=Asia/Seoul date +%F)"; mkdir -p "$SCRATCH"
```

```bash
# 키 불필요. 한국 종목은 005930.KS / 코스닥은 .KQ. 표준 라이브러리만 쓴다.
python3 scripts/fetch_ohlcv.py <TICKER> --range 2y  --interval 1d  -o "$SCRATCH/<TICKER>-1d.json"
python3 scripts/fetch_ohlcv.py <TICKER> --range 5y  --interval 1wk -o "$SCRATCH/<TICKER>-1wk.json"
```

- 받은 원자료를 **스크래치패드에 파일로 저장하고**, 모든 지표는 그 파일에서 계산한다.
  화면에 뜬 값을 눈으로 옮겨 적지 않는다.
- 스크립트 사용법·한계·수정주가 주의사항은 **`scripts/fetch_ohlcv.py`의 docstring이 마스터**다.
  여기 옮겨 적지 말고 `--help`로 확인한다.
- **미확정 봉은 스크립트가 판정한다.** 일봉은 **거래소 정규장 시간** 기준이라 미국 장이 KST 자정을
  넘겨 열려 있는 새벽(00:00~05:00)에도 잡히고, 주봉·월봉은 **장이 닫혀 있어도** 진행 중인 주·달의
  봉이 미확정이다. `[주의] 마지막 봉이 미확정이다`가 뜨면 5단계에서 `--drop-unconfirmed`로 제외한다.
  **원자료 JSON을 직접 잘라내지 않는다** — 자르는 판단은 스크립트가 하고 `--emit facts`에 기록으로 남아야 한다.
- **휴장으로 기준 종가일이 당일보다 밀리는 것은 정상이다.** 마지막 봉이 며칠 전이어도 그 확정
  종가를 쓰고, 며칠이 비었는지와 그 사유(연휴·주말)를 0절 스냅샷 괄호에 함께 적는다.
  데이터가 없다고 시장을 바꾸지 않는다(2단계).
- 장중에 바뀌는 값이므로 **조회 시각(KST)과 기준 종가일**을 함께 적는다.
- **회사의 좋고 나쁨의 근거로 쓰지 않는다.** "주가가 1년간 30% 하락했다"는 사실 기술이고,
  "그래서 싸다"는 이 저장소가 쓰지 않는 문장이다. 가격은 **타이밍 조건의 근거로만** 쓴다.
- 밸류에이션 배수(PER, PBR 등)를 2차 출처에서 그대로 옮기지 않는다. 쓰려면
  분모(EPS, BPS 등)를 공시에서 확인하고 직접 계산해 **계산식을 함께 남긴다.**
- `## 출처`에 `(시장 데이터) Yahoo Finance — YYYY-MM-DD HH:MM KST 조회`로 구분해 적는다.

### 거시 지표 (선택 — 기본값은 "쓰지 않음")

거시는 **아무 종목에나 갖다 붙일 수 있다.** 그래서 게이트가 없으면 매수 서사에 맞는 지표만
고르게 된다 — "금리가 내려가서 수혜"는 이 저장소가 금지한 예측 서술의 가장 흔한 형태다.

**게이트 — 아래 중 하나를 만족할 때만 쓴다. 둘 다 아니면 이 단계를 건너뛴다.**

1. **회사가 자기 공시에서 그 변수를 언급했다.** 환율 민감도, 이자율 위험, 원자재 가격 연동
   계약, 금리부 자산·부채 — 사업보고서의 시장위험 공시나 10-K의 Item 7A에 있는 것.
2. **사업 구조상 기계적으로 연결된다.** 은행의 예대마진과 기준금리, 수출 비중이 큰 회사의
   환율처럼 **연결 경로를 한 문장으로 쓸 수 있는** 경우.

연결고리를 **공시에서 찾지 못하면 쓰지 않는다.** "업황이 거시에 민감하다" 같은 일반론은 게이트를
통과하지 못한다. 게이트를 통과했으면 그 근거가 된 **공시 문장을 4절이나 5절에 함께 인용한다.**

```bash
# 코드를 모르면 먼저 찾는다 — 시리즈 ID·항목 코드를 기억에서 쓰지 않는다.
python3 scripts/fetch_macro.py fred --find "mortgage rate"
python3 scripts/fetch_macro.py ecos --find "환율"      # 통계표 → 그다음 --find 731Y001 로 항목
```

```bash
# 미국(FRED) / 한국(ECOS). 키는 환경변수 우선, 없으면 .env — 스크립트가 알아서 찾는다.
python3 scripts/fetch_macro.py fred DGS10 --start 2023-09-24 -o "$SCRATCH/macro-DGS10.json"
python3 scripts/fetch_macro.py ecos 722Y001/D/0101000 --start 2023-09-24 -o "$SCRATCH/macro-baserate.json"
```

**쓰는 자리는 정해져 있다. 「11. 거시 환경」 같은 절을 새로 만들지 않는다** — 절이 생기면 매번
채우려고 억지 연결을 만들게 된다.

| 절 | 거시가 하는 일 | 쓰면 안 되는 것 |
|---|---|---|
| 5. 재무 해석 | 공시 숫자의 **원인 후보**. "순이자마진 하락(공시)은 같은 기간 기준금리 인하와 방향이 같다" | 인과 단정 |
| 8. 논점 | 논거의 **트리거·기각 신호**. 거시가 가장 값어치 있는 자리다 | 거시만으로 선 논거 |
| 9. 매매 계획 | **무효화 조건**으로만. 근거 태그는 `[이벤트]` | 진입 조건의 근거 |
| 10. 재평가 시점 | **발표 예정일**. FOMC·CPI·금통위는 날짜가 확정돼 있어 "날짜를 적는다" 규칙과 맞는다 | "지켜본다" |

- **관측일과 조회일을 함께 적는다.** 거시는 개정(revision)된다 — 같은 관측일의 값이 다음 달에
  달라질 수 있다. 가격 데이터에 기준 종가일을 적는 것과 같은 이유다. FRED는 vintage를 주지만
  **ECOS는 주지 않는다**(스크립트가 `[주의]`로 찍는다).
- **발표 지연을 조회일로 덮지 않는다.** 07:00 실행 시점에 일별 계열은 1~3영업일, 월별 계열은
  한 달 이상 밀려 있다. 스크립트의 `[주의] 최신 관측이 N일 전`이 뜨면 **관측일 기준으로 서술한다.**
- 변환값(전년 대비 %)은 API가 아니라 **저장된 원자료에서 스크립트가 계산한 값**을 쓴다
  (`--from-file`로 재계산된다). 5단계의 규칙이 거시에도 같이 적용된다.
- **키가 없으면 그 경로를 포기한다.** 거시 없이 브리프를 쓰고, 생략 사실을 "방법론 · 재현"에 적는다.
- `## 출처`에 `(거시) FRED <시리즈 ID> — 관측일 YYYY-MM-DD, YYYY-MM-DD HH:MM KST 조회`로 적는다.
  ECOS는 `(거시) ECOS <통계표/주기/항목>` 형식으로 같이 쓴다.

## 5단계 — 지표 계산 규칙

**지표는 후행 지표다. 지표로 논거를 만들지 않는다 — 논거는 공시에서, 지표는 타이밍에서 쓴다.**

파라미터는 아래로 고정한다. 종목마다 바꾸면 보고서끼리 비교가 안 된다.

| 묶음 | 지표 | 파라미터 |
|---|---|---|
| 추세 | 단순이동평균(SMA) | 20 / 60 / 120 / 200일, 정배열 여부와 현재가의 상대 위치 |
| 모멘텀 | RSI | 14일, Wilder 평활 |
| 모멘텀 | MACD | 12 / 26 / 9 (EMA) |
| 변동성 | ATR | 14일, Wilder 평활 (절대값과 현재가 대비 %) |
| 변동성 | 볼린저 밴드 | 20일, ±2σ |
| 위치 | 52주 최고/최저 대비 위치 | (현재가 − 저) ÷ (고 − 저), % |
| 위치 | 기간 수익률 | 1M / 3M / 6M / 12M |
| 수급 | 거래량 배수 | 최근 거래일 거래량 ÷ 20일 평균 |

지지선/저항선은 스윙 클러스터로 잡는다.

- **일봉(최근 1년)**: 고가/저가가 **전후 5거래일** 내 최고/최저면 스윙 포인트로 보고, 가격 기준 **±2%** 이내를 한 클러스터로 묶는다.
- **주봉(최근 5년)**: 전후 **5주** 창, **±3%** 클러스터. 일봉과 창이 달라 값이 다르게 나오는 것이 정상이다.
- 터치 횟수는 클러스터에 묶인 스윙 포인트 개수이며 **강도의 근사치일 뿐 미래 지지·저항을 보장하지 않는다.**
- 유효한 클러스터가 2개면 2개만 쓴다. 3개로 억지로 채우지 않는다.

계산은 `scripts/technicals.py`로 한다. **네트워크를 쓰지 않고 저장된 파일만 읽으므로, 같은 파일을 넣으면 언제나 같은 값이 나온다.**

```bash
D="$SCRATCH/<TICKER>-1d.json"; W="$SCRATCH/<TICKER>-1wk.json"
python3 scripts/technicals.py "$D" --drop-unconfirmed --emit table   # 7절 지표 표
python3 scripts/technicals.py "$D" --drop-unconfirmed --emit levels  # 7절 일봉 지지/저항
python3 scripts/technicals.py "$W" --interval-preset weekly --drop-unconfirmed --emit levels
python3 scripts/technicals.py "$D" --drop-unconfirmed --emit facts   # 방법론 · 재현
```

- `--emit` 출력은 **손대지 말고 그대로** 붙여넣는다. 값을 손으로 고치면 원자료와 어긋나고 나중에 못 찾는다.
- **`--drop-unconfirmed`를 기본으로 쓴다.** 제외된 봉은 `--emit facts`에 사유와 함께 남으므로
  보고서가 그 판단을 그대로 담는다. 주봉은 진행 중인 주 + Yahoo가 덧붙인 중복 봉으로 **두 개가 빠질 수 있다.**
  그때 주봉 표의 현재가는 마지막 **확정** 주봉 종가이므로 일봉의 기준 종가일과 다르다 —
  주봉 표에서는 **레벨 값만** 가져오고, 보고서의 기준 종가일은 일봉을 따른다(표 아래 경고가 이를 알려준다).
- 지표 표는 **일봉으로 만든다.** 주봉 파일은 다년 지지/저항용이다(주봉 이동평균은 단위가 주라 일봉과 섞어 읽지 않는다).
- 파라미터·정의·한계는 **`scripts/technicals.py`의 docstring이 마스터**다. 여기 옮겨 적지 않는다.

지켜야 할 것:

- 실행한 커맨드를 보고서 `## 방법론 · 재현`에 그대로 적는다(`--emit facts`가 그 줄을 만들어 준다).
- **수정주가(배당·분할 반영) 여부를 명시한다**(`--price-field close|adjclose`). 표기 기준을 섞지 않는다.
- 상장 6개월 미만이거나 거래일이 부족하면 지표를 만들지 말고 **"표본 부족"으로 남긴다**(스크립트가 30봉 미만이면 중단한다).
- 원자료 마지막 종가일과 보고서의 모든 가격 기준일을 **하나로 통일**한다.
- **"원거리" 또는 "지지·저항 공백 구간" 경고가 붙은 레벨을 무효화 조건의 근거로 쓰지 않는다.**
  현재가에서 25% 넘게 떨어진 레벨은 손절 근거가 못 된다 — ATR 배수 같은 다른 기준을 쓰고 그 사유를 남긴다.

## 6단계 — 매매 조건 작성 규칙 (이 저장소의 핵심)

`## 9. 매매 계획`은 **예측이 아니라 조건문**이다. 아래를 지키지 않은 절은 발행하지 않는다.

1. **모든 줄은 "무엇이 관찰되면"으로 시작한다.** 시점 예측("다음 달쯤"), 확률 서술("가능성이 높다")은 쓰지 않는다.
2. **조건은 검증 가능해야 한다.** 가격(종가 기준인지 장중인지 명시), 공시 항목, 발표 일정 중 하나로 쓴다.
   "시장이 안정되면" 같은 조건은 검증할 수 없으므로 금지다.
3. **무효화(손절) 조건은 진입 조건과 같은 정밀도로 쓴다.** 무효화 조건 없는 진입 조건은 쓰지 않는다.
   무효화는 두 종류를 모두 적는다 — **가격 무효화**(예: S2 종가 이탈)와 **논거 무효화**(예: 해당 계약 매출 인식이 다음 분기보고서에서 확인되지 않음).
4. **각 레벨에 근거 태그를 단다.** `[공시]`(밸류에이션·펀더멘털), `[기술]`(지지/저항·ATR), `[이벤트]`(일정) 중 하나.
   태그 없는 가격은 감(感)이므로 삭제한다.
5. **R(위험 1단위)을 계산해 적는다.** `R = 진입가 − 무효화가`. 1차 목표까지의 폭을 R의 배수로 적고,
   **1R 미만이면 1R 미만이라고 그대로 쓴다.** 비율을 좋게 보이려고 목표를 늘리지 않는다.
6. **이미 충족된 조건은 충족됐다고 쓴다.** 작성 시점에 진입 조건이 이미 만족됐으면 그렇게 적고, 조건을 새로 지어내지 않는다.
7. **포지션 크기·레버리지·자금 배분은 쓰지 않는다.** 저장소는 주인의 계좌 사정을 모른다.
8. **수익률을 약속하지 않는다.** "얼마를 번다"가 아니라 "이 조건이 깨지면 판다"가 이 절의 문장이다.

표 형식:

| 구분 | 조건 (관찰 가능) | 가격 / 레벨 | 근거 |
|---|---|---|---|
| 1차 진입 | `<조건>` | `$X` | `[기술]` S1 클러스터(터치 n회) |
| 2차 진입 | `<조건>` | `$Y` | `[공시]` 밸류에이션 하단 |
| 진입 보류 | `<이 조건이면 진입하지 않는다>` | — | `[이벤트]` 실적 발표 전 |
| 가격 무효화 | `<조건>` | `$Z` | `[기술]` S2 종가 이탈 |
| 논거 무효화 | `<어느 공시의 어느 항목이 어떻게 나오면>` | — | `[공시]` 다음 분기보고서 |
| 일부 정리 | `<조건>` | `$A` | `[기술]` R1 클러스터 |
| 전량 정리 · 재평가 | `<조건>` | `$B` | `[공시]`/`[이벤트]` |

표 아래에 **R 계산식 한 줄**과, **조건이 서로 충돌할 때 무엇을 우선하는지** 한 줄을 남긴다

## 8단계 — 검증

**주장이 아니라 증거로 통과시킨다.** 순서가 있다 — 기계가 볼 수 있는 것을 먼저 기계에게 맡기고,
사람과 다른 컨텍스트만 볼 수 있는 것을 그다음에 본다.

**① 형식 검사 (필수, 기계)**

```bash
python3 scripts/validate_brief.py briefs/<파일명>.md
```

파일명·머리 세 줄(h1 + 요약 두 줄, 첫 줄 60자·스탠스 일치)·빈 절·면책·금지 표현·
9절 구조(가격/논거 무효화, R 계산식, 근거 태그)·출처 절 필수 항목·기준 종가일 일관성을 본다.
**exit 0이 아니면 다음으로 가지 않는다.**

`!`로 시작하는 **경고는 커밋을 막지 않지만 그냥 넘기지 않는다.** 용어 풀이 경고(`처음 나올 때 뜻
풀이가 없다`)와 7절 비고 경고는 고치거나, 고치지 않은 사유를 `## 방법론 · 재현`에 한 줄 남긴다. 이 검사를 통과하지 못한 브리프는
커밋 훅이 막는다(`scripts/hooks/block_unverified_commit.sh`).

통과는 "옳다"가 아니라 "형식 때문에 틀릴 일은 없다"는 뜻이다. 숫자의 진위는 여기서 검사되지 않는다.

**② 교차 검증 (필수, 새 컨텍스트)**

`brief-verifier` 서브에이전트에 보고서 경로와 원자료 경로를 넘긴다. 그 에이전트는 이 브리프를 쓰지 않았으므로
작성 과정의 편향 없이 숫자를 원자료·출처 문서와 대조한다. **차단** 등급 발견이 하나라도 있으면 고치고 다시 돌린다.

자기가 쓴 보고서를 자기가 채점하지 않는다 — 방금 그 숫자를 쓴 컨텍스트는 같은 실수를 두 번 못 본다.

**검증이 실패했을 때** — ①과 ②는 스스로 고치고 다시 돌린다. 사용자에게 묻지 않는다.

상한은 둘이고, **먼저 걸리는 쪽에서 멈춘다.**

- 같은 지적을 **두 번** 고쳐도 통과하지 못하면 멈춘다.
- ②교차 검증은 **최대 3라운드**다. 3라운드에서 차단이 남으면 지적이 매번 달라지더라도 멈춘다.

원문에 없는 숫자를 지어내 통과시키는 것이 이 저장소에서 가장 나쁜 결말이고, 세 번째 시도는 대개
그쪽으로 간다. 통과를 위해 근거를 무르게 고치느니 미완으로 두는 편이 낫다.

**멈췄으면 흔적을 남긴다.** 무인 실행이라 커밋이 없으면 저장소에도 사이트에도 아무 기록이 없고,
주인은 그날 저녁에야 브리프가 없다는 것을 알게 된다. 그러므로 멈출 때는 이슈를 남긴다.

```bash
gh issue create --title "브리프 미완 $(TZ=Asia/Seoul date +%F) — <종목>" --body "$(cat <<'EOF'
남은 지적:
- (validate_brief.py 또는 brief-verifier의 차단 항목 그대로)

멈춘 사유: (같은 지적 2회 / 교차 검증 3라운드 중 무엇인가)
미완 브리프: (작성 중이던 파일 경로 — 커밋하지 않았다)
원자료: ($SCRATCH 경로를 그대로 적는다)
EOF
)"
```

미완 브리프 파일은 **커밋하지 않는다.** 검증을 통과하지 않은 문서가 사이트에 올라가는 경로는 없다.

**③ 아래 체크리스트 (①②가 볼 수 없는 것만)**

형식은 ①이 보고, 숫자의 재현은 ②가 본다. **여기서 세 번째로 같은 것을 보지 않는다** — 그건 무인
실행에서 순수한 비용이다. 남는 것은 기계도 리뷰어도 판정할 수 없는 것들이다.
**통과 근거를 증거와 함께 보고한다** ("확인했다"는 주장만으로는 부족하다).

- [ ] 모든 수치가 `## 출처`의 특정 문서로 추적되는가. 추적 안 되는 수치는 삭제한다.
      (시장 데이터는 예외 — 대신 조회 시각과 기준 종가일이 적혀 있는가.)
- [ ] 단위·통화·기간(연결/별도, 분기/누적, KRW/USD, GAAP/Non-GAAP)을 원문과 대조했는가.
- [ ] 최근 7일 제외 목록과 오늘 파일 유무를 **명령으로** 확인했는가(기억으로 판단하지 않았는가).
- [ ] 점수표의 ②가 0인 후보를 고르지 않았는가. ③⑤ 점수가 실제 지표 출력과 맞는가.
- [ ] 각 레벨의 `[공시]`/`[기술]`/`[이벤트]` 태그가 **실제 근거와 맞는가**(기술적 레벨에 [공시]를 달지 않았는가).
- [ ] 약세 논거가 강세 논거와 같은 밀도로 쓰였는가(트리거·기각 신호 포함).
- [ ] 8절·9절이 서로 모순되지 않는가(약세 논거가 진입 조건을 이미 무효화하고 있지 않은가).
- [ ] 2차 자료의 숫자를 옮긴 문장이 남아 있지 않은가.

## 9단계 — 커밋 · 푸시

검증을 통과했으면 멈추지 않고 커밋까지 간다. 메시지 형식은 `AGENTS.md`의 "커밋"에 있다.

```bash
git add briefs/<파일명>.md
git commit -m "brief(YYYY-MM-DD): <종목명> — <한 줄 요약>"
git push origin main
```

- 보고서 1건 = 커밋 1건. 브리프와 저장소 문서 수정을 한 커밋에 섞지 않는다.
- 푸시하면 사이트가 자동 배포된다(`.github/workflows/deploy.yml`). **공개되는 문서라는 뜻이다** —
  8단계를 건너뛰고 오는 경로는 없다.
- 커밋 훅이 검증을 다시 돌리므로, 여기서 막히면 8단계로 돌아간다.

### 배포 확인

푸시가 곧 게시는 아니다. 배포가 끝났는지 **확인한 뒤** 보고한다.

```bash
gh run list --workflow=deploy.yml --limit 3
curl -s -o /dev/null -w "%{http_code}\n" \
  https://parkgyeongtae.github.io/daily-equity-brief/briefs/<파일명>
```

200이면 됐고, 목록 페이지에 종목명이 뜨는지도 본다.

**브리프가 사이트에 안 보일 때** — 원인은 대개 파일이나 파서가 아니라 배포다.
`build` 잡은 성공하는데 `deploy` 잡이 `waiting`에서 `queued`로 넘어가지 못하고 멈추는 일이 있다
(정상일 땐 waiting → queued 가 수 초다. 2026-09-23 보령(003850) 브리프에서 27분 정체).
이 저장소에는 환경 보호 규칙(승인자·대기 타이머)이 없으므로 설정 문제가 아니라 GitHub 쪽 큐 정체다.
`gh api repos/ParkGyeongTae/daily-equity-brief/deployments/<id>/statuses`로 확인할 수 있다.

복구는 **취소가 먼저**다. 워크플로에 `concurrency: {group: pages, cancel-in-progress: false}`가
걸려 있어, 멈춘 런을 그대로 두고 새로 트리거하면 새 런이 뒤에 줄만 서고 똑같이 멈춘다.

```bash
gh run cancel <멈춘 런 ID>
gh workflow run deploy.yml --ref main
```

배포가 끝내 실패하거나 복구가 듣지 않으면 **8단계의 `gh issue create`와 같은 방식으로 이슈를 남긴다.**
브리프는 커밋됐는데 사이트에 안 보이는 상태가 조용히 지나가면 안 된다.
